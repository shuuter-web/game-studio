# Voxel Mine v0.2.0 — 遠征状態の導入

## 設計判断

2026-09-20、producerの受入条件とtech-leadの技術レビューを受けて実装。既存の単一HTML、Canvasの手描き描画、シード生成を維持する。拡張全体は `docs/gdd/voxel-mine-expeditions.md` に記す。

### 状態と境界

- 拠点・探索・帰還処理を区別する。燃料とターンは遠征状態に保持し、UI表示から独立して採掘関数側で制約を適用する。
- 行き先は既存生成レベル1〜6に対応するデータ定義。航路レベルで開放を判定し、出航関数でもロックを検査する。
- タンク容量・航路費用は段階別のデータ定義にまとめ、既存工房の仕組みへ接続する。
- 装備の更新は拠点のみ。単にボタンを隠すのではなくクラフト関数にも制限を置く。
- 同一の世界種と行き先では同じ島を生成する。再訪時は鉱床を回復、遠征中の再読込では保存済み島を復元する。

### 採掘トランザクション

有効な対象への一撃で燃料1・ターン1を計上し、範囲と連鎖の報酬をその一撃に所属させる。空セル・硬さ不足は燃料を使わない。新しい一撃の前に前の連鎖を処理済みにするか入力を保留し、連鎖の所属を混ぜない。

コンボは一撃とその連鎖内で計上し、実時間による期限を廃止する。既存実装の連鎖からの再帰的な連鎖予約は、表示された最大連鎖数を超えないようにする。

燃料0または任意帰還では、未確定の連鎖を捨てず処理してから拠点へ移行する。獲得素材は保持し、次の出航で無料補給する。

### 保存

v2に遠征状態・燃料・ターン・連鎖予約・コンボを追加する。予約時刻は再読込後の時計に合わせて復元できる相対時間とする。有効採掘と連鎖報酬の処理に合わせて保存する。

v1は検証してから在庫・装備・統計を移行し、到達済み島に相当する航路を付与して拠点へ戻す。異常なデータは部分的にゲーム状態へ反映しない。`?fresh=1` は通常セーブを上書きしない検証用スロットにする。

### 検証

`node tools/check.mjs prototypes/voxel-mine/index.html` と `node prototypes/voxel-mine/verify.mjs` で判定する。後者はPlaywrightを使用し、モジュールとブラウザの実行パスを環境変数で指定できるようにする。

受入条件：初回出航、航路ロック、費用不足、初期島だけで初回強化可能、部分打撃の燃料消費、硬さ不足と空振りの無料判定、範囲・連鎖の1回消費、最終手の連鎖帰還、保存再開、旧セーブ移行、同seed再訪、異なる画面幅での操作可能性。実機の触り心地と燃料バランスは自動検査結果とは分けて報告する。
