# Dragon Tide 案帳の運用（チケットの流れ・定時チェック）

（2026-11-07 に CLAUDE.md から移した。案帳まわりの決まりはここが正本）

地域・竜種・特殊個体・ラッシュイベント・敵などの案は、チャットに並べて終わらせず、
案チケットボード「Dragon Tide 案帳」に1案1チケットで足す（Shooter が採用・保留・要修正・不採用とコメントを書き込む場所）。

https://claude.ai/artifact/QCAvoU291kLKCVQsKuQahX

- 読み書きは `ArtifactData`（コレクション `tickets`、doc id ＝ `DT-001` からの通し番号）。
  項目：`no` `kind` `batch` `title` `hook` `star` `fields`（`{label, text}` の配列）`status` `thread` `order` `createdAt` `updatedAt`
- **作業を始める前に判定を読む**。チケットは採用後も同じチケットで実装・確認・完了まで追う。
  ステータスと流れ（2026-10-21 Shooter と合意）：

  | 段階 | ステータス | 役割 | この状態にする人 | 次の番 | 次へ |
  |---|---|---|---|---|---|
  | 判定 | 未判定 | Claude が出した・直した案。判定待ち | Claude | Shooter | 実装待ち・要修正・保留・不採用・済み（別件等） |
  | 判定 | 要修正 | 案を直してほしい（作る前なら、採用後の実装待ち・返答待ち・実装中からも戻せる） | Shooter（コメント付き） | Claude | 未判定（直した版に差し替え） |
  | 判定 | 保留 | 今はやらない。捨てない | Shooter | — | Shooter が見直したら未判定・実装待ち |
  | 判定 | 不採用 | やらない。消さずに残す | Shooter | — | 原則そのまま |
  | 判定 | 済み（別件等） | 別件で済んだ・ほかのチケットと重複している（作る前の実装待ち・返答待ち・実装中からも移せる） | Shooter | — | 原則そのまま |
  | 実装 | 実装待ち | 採用。Claude の着手待ち | Shooter（「採用して「実装待ち」にする」） | Claude | 実装中・返答待ち・要修正 |
  | 実装 | 返答待ち | 採用済み。Claude が質問・実装方針を書いて返事待ち | Claude | Shooter | 実装待ち（返事をして戻す）・要修正（実装に進まず案を直す） |
  | 実装 | 実装中 | Claude が作っている | Claude | Claude | 実装済・返答待ち |
  | 実装 | 実装済 | master に反映した。確認待ち | Claude（プレビューリンク付き） | Shooter | 完了・手直し |
  | 実装 | 手直し | 実装を直してほしい | Shooter（コメント付き） | Claude | 実装済 |
  | 実装 | 完了 | 確かめて OK。おしまい | Shooter だけ | — | 追加の要望が出たら、そのたびに手直しに戻すか新しいチケットにするかを選ぶ |

  - Claude が状態を動かしたら、必ず `thread` に `{by: "claude", text, at}` で何をしたかを書く
  - 案帳のボタン名には、押した後のステータス名を必ず入れる（例「採用して「実装待ち」にする」）
  - 「採用するが実装方法を先に確認して」と言われた案は、方針を `thread` に書いて **返答待ち** にする（実装待ちのまま待たない）
  - 完了後の追加の要望：Shooter が指定しなければ、同じ機能の調整は手直しに戻し、新しい要素は新しいチケット（未判定）にする
  - 実装中のまま会話が終わったら、3時間以上動きの無い「実装中」を次の会話の Claude が引き継いで再開する（定時チェックの節を参照）
  - 大きな案を何回かに分けて作るときは、1回分を master に反映するたびに実装済にする
  - Claude が作業中に気づいた不具合・改善は、新しいチケット（未判定）として出す。勝手に実装待ちにしない
  - 作る前（実装待ち・返答待ち・実装中）に「要修正」へ戻されたら、ゲームの実装には進まず、案をチケットで直して「未判定」で返す（2026-10-21 Shooter指示）
  - 別件で済んでいる・重複していると Claude が気づいたら、何で済んだか（DT番号・版）をコメントに書いて Shooter に知らせる。「済み（別件等）」にするのは Shooter（2026-10-23 合意。「不採用」と分けるのは、不採用を見返すときに混ざらないようにするため）
  - Shooter も案帳の「＋ チケットを足す」からチケットを足せる（2026-10-24。`createdBy: "shooter"`、batch は「日付 Shooter が足した案」）。足したときの状態は「実装待ち（作ってほしい）」「要修正（案を詰めてほしい）」「保留（メモ）」のどれか。要修正で足されたチケットは、Claude が案に仕立て直して（地域・敵・付加イベントなら絵も付けて）「未判定」で返す
  - 古い `採用` は `実装待ち` として読む
  - Shooter のコメントには画像が付くことがある（2026-10-25。`thread` の項目の `images` に案帳の画像置き場の id の配列）。
    中身は `Artifact` の `read`（`url` に案帳、`path` にその id）で手元に落として見る
- **定時チェック**（2026-11-01 Shooter と合意）：2時間ごと（2〜6時を除く）に**毎回新しい会話**が立ち上がって案帳を見る。
  起動文は trigger `trig_012Hat6idgbmKW4dvCYFiDpa` に保存されている（定時チェックの会話からは書き換えられない。食い違ったらこのファイルを優先）
  - **対象は「Claude の番」のチケットだけ**（DT-512）：`status` が `実装待ち`・`手直し`・`要修正`（古い `採用` も含める）のもの、と3時間以上動きの無い `実装中` を query する。
    Shooter の番のチケット（未判定・返答待ち・実装済・保留など）は、コメントが付いても触らない（返事をした返答待ちは、Shooter が実装待ちか要修正に戻したときに拾う）
  - **対象のチケットは、その回でなくなるまで処理する**（2026-11-07 Shooter指示）。数件やって残りを次の回に回さない。
    1件（または数件まとめて）反映して実装済にしたら、もう一度 query して0件になるまで続ける。次の回に回すのは使用量の制限で続けられないときだけ
    （途中のチケットは thread にどこまで済んだかを書いておく）。迷う判断は質問を書いて返答待ちにし、次のチケットへ進む
  - 取りかかるチケットは先に「実装中」にして `thread` に書く。**別の回が「実装中」にしてから3時間たっていないチケットには触らない**（二重に作らないため）
  - **3時間以上動きの無い「実装中」は引き継ぐ**（2026-11-05 Shooter指示）：`statusAt` と `thread` の最後の書き込みがどちらも3時間以上前なら、
    前の回が途中で止まったとみなす。thread に「引き継ぎます」と書いてから、master とチケットのやり取りで前の回がどこまで進んだかを確かめて続きを作る
  - master へ push する前に必ず `git pull` で最新を取り込む
  - 確認した記録として、始めた時刻を `meta/lastCheck` の `at` に書く
  - 時刻：thread の本文や報告は日本時間（例「11/3 6:09」。UTC だと夜の予定と読み違えるため）。
    データの時刻欄（`updatedAt`・`statusAt`・`at`）は UTC の ISO 形式で、書き込む直前に `date -u +%Y-%m-%dT%H:%M:%S.000Z` で取った本当の時刻を入れる
  - 新しい会話はこれまでのチャットを知らない。**チャットで決めたことは、このファイル・CLAUDE.md・設計書・チケットのやり取りのどこかに必ず書き残す**
  - 案帳の「⚡ 今すぐ処理してもらう」ボタンは、見ている人の「Claude Code Remote」でこの定時チェックをその場で1回起動する
    （押した時刻は `meta/runNow`、5分は押せない）。定時チェックを作り直したら、案帳の `RUN_TRIGGER_ID` も書き換える
- **報告ポスト**（DT-553・2026-11-12）：案帳の右上「📝 報告だけの画面」で、同じページをチケットを足すだけの画面に切り替える（端末ごとに覚える。URL の `#post` でも開くが当てにしない）。
  同じページなので保存先は案帳と同じ。足したチケットは `createdVia: "post"`、種類は「不具合」（`kind: "不具合"`、既定の状態は実装待ち）・「改善」・「案」（`kind: "その他"`。この2つは既定で要修正）。
  ゲームの状況は `fields` の「状況（ゲームから）」に入る（不具合の調べ直しはここの版・シードを使う）。
  別のページ（受け箱）にしなかったのは、2枚目のページが案帳と同じ保存先に書けるか確かめる手段がなく、届かないと報告が消えるため
  - **ゲームがクリップボードに入れる文の形**（ゲーム側の「📝」はこの形で写す）：1行目が `【Dragon Tide 報告】`、続く行は `キー: 値`。
    `種類:`（不具合／改善／案）と `ひとこと:` は報告ポストの欄に入り、ほかの行（`版:` `シード:` `経過時間:` `ステージ:` `地域:` `竜種:` `特殊個体:` `敵:` など）は状況としてそのまま残る。
    題名が空のときは `地域:` と `竜種:` から「（地域）で（竜種）のとき」を作る。画面の絵は同じクリップボードに image/png で入れる
- 判定前の案はリポジトリに書かない（案帳が正本）。採用になった案だけ GDD に書き写す
- **地域・敵・付加イベントの案には、必ずトップビューの見え方の絵を付ける**（Shooter指示）。
  簡易な図・概念図でよい。このゲームはトップビューの画面が肝なので、案の時点で見え方まで考える。
  チケットの `sketch: { svg, caption }` に SVG（文字列。`<svg` で始める）と一文の説明を入れると、案帳のカードに出る。
  絵の語彙はゲーム画面に寄せる：街＝赤茶の屋根の点、首都＝赤い二重丸、竜の群れ＝橙の三角の集まり、
  プレイヤーの引く線＝白の点線、敵＝青灰、敵の弾＝黄、地面＝暗い緑（地域に合わせて変えてよい）
- 案の中身は各ゲームの設計書の恒久ルールに従う（Dragon Tide なら `docs/gdd/dragon-tide-next-steps.md` §4。
  地域だけに課していた §3-x の2点は 2026-10-21 に外した）。
  ゲームの芯（線を描く→群れがなぞる→薙ぐ→卵で増える→ジオラマ化）から発想した案も必ず混ぜる
