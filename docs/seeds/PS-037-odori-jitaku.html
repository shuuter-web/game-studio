をどり支度 ―季をめぐる宿―

古い京の宿を継ぎ、客ごとに「もてなしの一日」を設える

保留 京都Cozy旅館経営見送り 2026-06-26 idea-scout
※ 京都×Cozyスプリントの対抗。温泉もてなしの飽和（Spirittea/Onsen Master等）を避け「見送りの宿」に差別化。RPG進行版はSprint11「宿場の主 ―四季を継ぐ宿―」として別発想（未ファイル化）。

1. ログライン（What）

鴨川沿いの小さな宿を継ぎ、一見の客の事情（疲れ・祝い・別れ旅）を読み、部屋の設え・夕餉・朝の見送りを四季の行事に合わせて整える。温泉もてなしの飽和を避け、「見送り」の情緒に寄せた差別化された宿経営Cozy。

2. コアファンタジー（Why it feels good）

「この京の宿の主人になりたい」という経営×憧れの強い所有欲。客が一夜を過ごし旅立つときの表情と言葉が報酬となる、Spiritfarer的な“見送り”の情緒。

3. コアループ（何を繰り返すか）

今日の客の事情・季節を聞く（観察）→ 部屋の花・掛軸・夕餉・湯・朝餉を一日のもてなしとして組み立てる（取り合わせの判断）→ 客が一夜を過ごし旅立つときの表情と言葉が報酬（フィードバック）→ 評判で宿が育ち、行事（葵祭・大文字・除夜）ごとに新しい設えが解放（進行）。

4. フック / 新規性（Novelty）

  • いちばんのひねり：温泉もてなしCozyの飽和（Spirittea/Onsen Master/Bathhouse Creatures）を意図的に回避し、“見送りの宿”に寄せた。
  • 一目で伝わる引き：旅館/宿経営は実証Cozyジャンル。「京の宿の主人」というアスピレーションが強い。

5. 市場性（Market）

  • ターゲット：旅館・宿経営Cozy層、Spiritfarer的な感情の物語を求める層。
  • 参照タイトル：旅館経営Cozy。差別化は温泉でなく「見送り」の情緒に寄せた点。
  • 収益モデル：買い切り。
  • 配信先：Switch/モバイル/PC。
  • 追い風/逆風：追い風＝経営Cozyは実証済みで外しにくい。逆風＝「見送り」の情緒重視だとゲームプレイの反復性がやや弱く、感動止まりに寄りすぎないバランスが必要。

6. 面白さの核（Fun）

  • ジューシーポイント：客の事情にぴたりとハマる設えを組み、心から満足した表情を見る瞬間。
  • 上達の方向：客の事情から最適な取り合わせを読む観察眼と経験則の蓄積。
  • 中毒のフック：行事ごとに解放される新しい設え、常連客のエピソード。

7. 拡張性 / 伸びしろ（Stretch）

  • 縦に深まるか：もてなし技のバリエーション、宿の格上げ（増改築）。
  • 横に広がるか：行事イベント（葵祭・大文字・除夜）ごとの特別な設え。
  • 継続サイクル：季節ごとの客層の変化、常連客との関係進行。
  • アピールの面：床の間に花を生ける設えの一枚絵、四季の行事に合わせた宿の景色。
  • 天井とリスク：「見送り」に寄せすぎるとしっとり感動止まりのヒキになりがち。取り合わせの意思決定を毎回悩ましくする設計でヒキを担保する必要。

8. 検証すべき最大の賭け（Riskiest Assumption）

「もてなしの取り合わせ」判断が、単なる正解探しでなく毎回悩ましい意思決定として機能するか。最小プロトで客3パターン・設え要素5種のみを作り、取り合わせの手応えを検証する。

9. スコープ感

  • 最小プレイアブルに必要な要素（3つ）：①客の事情の提示、②設え・夕餉・湯の取り合わせUI、 ③満足度フィードバックと評判進行。
  • 技術リスク／未知数：客の事情と満足度判定のロジック設計（正解探しにならない工夫）。
  • 規模感：コアプロトは数週間。フル開発は中規模。
