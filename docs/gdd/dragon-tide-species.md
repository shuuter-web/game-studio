## 1. 設計の骨（第1案からの修正点）

### 1-1. 既存4種は「名前そのまま・動きは共通のスタンダード」

第1案では既存4種を体躯の名前（鷲竜・隼竜…）へ改名したが、**これは却下**（ユーザー指摘・2026-08-08）。
理由は明快で、**一番の差別化要素である攻撃手段が名前から分からなくなる**。
火竜／氷竜／影竜／緋竜という属性名は「何を撃つか」を正しく伝えている。

→ **既存4種は名前を維持し、動きは4種すべて同一のスタンダードに戻す。**

これで「操作感の違いに納得感がない」という元の問題は**改名ではなく統一で解決する**。
属性名は攻撃を表し、動きに差が無いので説明の要らない状態になる。

| 竜 | English | 攻撃 | 動き |
|---|---|---|---|
| 🔥 **火竜** | Fire Dragon | 炎息（持続照射・近距離） | **スタンダード** |
| ❄️ **氷竜** | Ice Dragon | 氷槍（直進貫通弾） | **スタンダード** |
| 🌑 **影竜** | Shadow Dragon | 影弾（加速ホーミング＋着弾円） | **スタンダード** |
| 🐾 **緋竜** | Crimson Dragon | 爪撃（体当たり） | **スタンダード** |

スタンダード = 現行 `MOVE_PROFILE_DEFAULT`（`maxSpeed 160 / minSpeed 60 / accel 320 / turnRate 2.0 /
leaderSpeed 220 / leaderPull 1.6 / recoil 0 / fireStun 0 / pathEndMode "loop"`）。

**やること**：現行 `SPECIES_MOVEMENT` の bullet（`recoil 18` `fireStun 0.04` `turnRate 2.8` 等）・
missile・melee の上書きを**削除**して4種すべて既定値にする。
※体当たりの `HITSTOP_DURATION`（0.048秒）は竜種特性ではなく衝突全般の演出なので残す。
　緋竜だけの `fireStun 0.14` は撤去する。

### 1-2. 動きの多様性は「新種側」が担う

**名前が正体を説明し、正体から動きが推測できる**ものを新種に置く。
竜に限らず機械・現象・非生物も混ぜる（ユーザー方針）。名前の字数・漢字にはこだわらない。

### 1-3. 構造（第1案から変更なし・承認済み）

**現状は「竜種 = 攻撃タイプ」の1対1**。`flockWeapon` が4値しかなく、動きも `SPECIES_MOVEMENT[flockWeapon]`
で引いている。**`SPECIES_DEFS` を新設して「攻撃 × 動き × 見た目」の組にする。**

```js
const SPECIES_DEFS = {
  fire:   { ja:"火竜",   en:"Fire Dragon",   attack:"flamebreath", move:"standard", sprite:"dragon_fire",   unlock:null },
  falcon: { ja:"隼竜",   en:"Falcon Dragon", attack:"wingblade",   move:{…},        sprite:"dragon_falcon", unlock:{…} },
  ufo:    { ja:"UFO",    en:"Saucer",        attack:"tractorbeam", move:"instant",  sprite:"ufo",           unlock:{…} },
  …
};
```

- `flockWeapon` は「攻撃タイプ」を指す内部値に戻し、竜種IDは `flockSpecies` として別に持つ。
- 影響範囲：`SPECIES_CHOICES` / `WEAPON_HUD` / `WEAPON_ELEMENT` / `mv()` /
  `CARD_DEFS` の `weapon:` フィルタ（→ `species:` へ拡張）/ ランセーブ（`flockWeapon` を保存中）。
- 攻撃を `ATTACK_DEFS` として独立させれば、**攻撃と竜種を自由に組み替えられる**
  （同じ攻撃を別の動きで出す＝将来の種増やしが安い）。

## 4. アセット（1種 = 1枚。節約しない方針）

`assets/dragon_<id>.png` として**竜種ごとに専用スプライトを1枚**持つ。

| 状態 | 対象 |
|---|---|
| 既存流用 | 火竜（`dragon_fire_body` + `dragon_fire_wing`）／氷竜（`dragon_ice`）／影竜（`dragon_shadow`） |
| **新規（12枚）** | 緋竜（現状 fire の赤ティント → 専用画に）／隼竜／燕竜／蜂竜／**UFO**／鬼火／ガーゴイル／雷雲竜／鶴竜／鮫竜／亀竜／鯨竜 |

- **トップビュー厳守**。立面・ドームで描かない（過去に差し戻し実績あり）。
- プリレンダは属性×羽ばたき16コマ。**15種 × 16コマ**になるので、
  火竜1属性で約672KB → 全種プリレンダはメモリが厳しい。
  **選択中の1種のみプリレンダ**する形に変える必要がある（`dragonSprites` の生成タイミング）。
- UFO・鬼火は羽ばたきが無いので**コマ数を減らせる**（別の周期アニメ＝回転・明滅にする）。
- 生成は `/gen-game-asset`（Gemini）と `C:\forge\ClaudeCodeForge`（Forge）で賄える見込み。
  トップビューの単体シルエットなので**人間製素材が大量に要る案ではない**。

## 5. UI とアンロック

- **4択メニューは15種に耐えない**（`showSpeciesSelect` はカードを縦積み）。
  グリッド＋スクロール、かつ**アンロック済みのみ表示**へ。
- 解放は `CHALLENGE_DEFS` / `evaluateChallenges` に接続（next-steps §3-7 の二層経済と噛む）。
  初期解放は**火竜のみ**、Ⅰ群の残り3種は早期に、Ⅱ〜Ⅴは腕前で解く。
- **UFO は隠し枠**にすると収まりが良い（世界観から外れる存在なので、
  条件を満たしたときだけ出てくる方が「変なものが混じった」驚きになる）。
- **専用カード**：`CARD_DEFS` の `weapon:` を `species:` に拡張。15種×3〜4枚だと45〜60枚なので段階投入。

## 6. 進め方の推奨

1. **Ⅰ群の統一を先にやる**（`SPECIES_MOVEMENT` の上書き削除）。コード削除だけで済み、
   「4種の操作感が同じ」状態を実機で確認できる。
2. **`SPECIES_DEFS` / `ATTACK_DEFS` の分離**（構造変更のみ。挙動は変えない）。
3. **Ⅱ群3種＋ガーゴイル**を追加（攻撃はすべて「軽」段）。動きの違いが効くかを4種で判定。
4. 通れば **UFO・鬼火**（非生物枠）→ Ⅳ・Ⅴ群（重い攻撃）へ。
5. アセットは各段で必要ぶんだけ生成する。

## 7. 未決の論点

1. **緋竜の硬直**：`fireStun 0.14` を撤去して完全にスタンダードに揃えるか、
   「体当たりの重さ」は攻撃側の演出として残すか。本書は**撤去**を前提にした。
2. **プリレンダのメモリ**：15種を全部持つと厳しい（§4）。選択中の1種のみ生成に変える前提。
3. **UFO の世界観**：竜が卵を奪還する物語に円盤が混じる。隠し枠にする案を書いたが、
   もっと堂々と出す方が面白いなら初期から選択可にしてもよい。
4. **予備の攻撃9種（A16〜A24）**：新種に割り当てるか、既存種の**上位進化**に回すか
   （next-steps §3-2 型D「2枚maxで上位カードが出現」との相性が良い）。
5. **動きの系統は5つで足りるか**：軽量／標準／重量／超鈍重／即時 の5系統に集約されている。
   プレイヤーが違いを感じるのはこの5つなので、**同系統内の差（隼竜と燕竜など）は
   攻撃と見た目で作る**ことになる。それで十分かは実機判断。
