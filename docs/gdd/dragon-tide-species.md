## 1. 設計の骨（第1案からの修正点）

### 1-1. 既存4種は「名前そのまま・動きは共通のスタンダード」

第1案では既存4種を体躯の名前（鷲竜・隼竜…）へ改名したが、**これは却下**（ユーザー指摘・2026-08-08）。
理由は明快で、**一番の差別化要素である攻撃手段が名前から分からなくなる**。
火竜／氷竜／影竜／緋竜という属性名は「何を撃つか」を正しく伝えている。

→ **既存4種は名前を維持し、動きは4種すべて同一のスタンダードに戻す。**

これで「操作感の違いに納得感がない」という元の問題は**改名ではなく統一で解決する**。
属性名は攻撃を表し、動きに差が無いので説明の要らない状態になる。

| 竜 | English | 攻撃 | 動き |
|---|---|---|---|
| 🔥 **火竜** | Fire Dragon | 炎息（持続照射・近距離） | **スタンダード** |
| ❄️ **氷竜** | Ice Dragon | 氷槍（直進貫通弾） | **スタンダード** |
| 🌑 **影竜** | Shadow Dragon | 影弾（加速ホーミング＋着弾円） | **スタンダード** |
| 🐾 **緋竜** | Crimson Dragon | 爪撃（体当たり） | **スタンダード** |

スタンダード = 現行 `MOVE_PROFILE_DEFAULT` の**移動パラメータ**
（`maxSpeed 160 / minSpeed 60 / accel 320 / turnRate 2.0 / leaderSpeed 220 / leaderPull 1.6 / pathEndMode "loop"`）。

**★重要な分類の変更（決定事項1）**：`recoil`（反動）と `fireStun`（硬直）は
**移動プロファイルではなく攻撃に属する**。「体当たりの硬直は操作性ではなく攻撃手段に付随するもの」
（ユーザー判断）だから。よって：

| パラメータ | 帰属 | 4種の扱い |
|---|---|---|
| `maxSpeed` / `minSpeed` / `accel` / `turnRate` / `leaderSpeed` / `leaderPull` / `pathEndMode` | **動き**（`SPECIES_DEFS.move`） | 4種すべて同一のスタンダードに統一 |
| `recoil` / `fireStun` | **攻撃**（`ATTACK_DEFS`） | 攻撃ごとの個性として**残す** |

**やること**：`SPECIES_MOVEMENT` の bullet/missile/melee の上書きのうち
**移動パラメータぶんだけ削除**（`turnRate 2.8`・`maxSpeed 175`・`accel`・`pathEndMode` 等）。
`recoil` / `fireStun` は `ATTACK_DEFS` へ移設して維持する。

- 爪撃（緋竜）: `fireStun 0.14` を**維持**（体当たりの重さ）。衝突全般の `HITSTOP_DURATION`（0.048秒）とは別物。
- 氷槍（氷竜）: `recoil 18` も同じ理屈で**攻撃の個性として維持**する前提にした。
  ※ここは判断が分かれうる。「4種は完全に同じ手触りにしたい」なら氷槍の反動は0にできる（1行）。

### 1-2. 動きの多様性は「新種側」が担う

**名前が正体を説明し、正体から動きが推測できる**ものを新種に置く。
竜に限らず機械・現象・非生物も混ぜる（ユーザー方針）。名前の字数・漢字にはこだわらない。

### 1-3. 構造（第1案から変更なし・承認済み）

**現状は「竜種 = 攻撃タイプ」の1対1**。`flockWeapon` が4値しかなく、動きも `SPECIES_MOVEMENT[flockWeapon]`
で引いている。**`SPECIES_DEFS` を新設して「攻撃 × 動き × 見た目」の組にする。**

```js
// 攻撃：図形・威力・反動・硬直を持つ。竜種から独立させて組み替え可能にする。
const ATTACK_DEFS = {
  flamebreath: { ja:"炎息", en:"Flamebreath", kind:"beam",   recoil:0,  fireStun:0    },
  icelance:    { ja:"氷槍", en:"Ice Lance",   kind:"bullet", recoil:18, fireStun:0    },
  rend:        { ja:"爪撃", en:"Rend",        kind:"melee",  recoil:0,  fireStun:0.14 },
  …
};

// 竜種：攻撃 × 動き × 見た目。move は**毎種フルに書く**（プリセット名では持たない。決定事項5）
const SPECIES_DEFS = {
  fire: {
    ja:"火竜", en:"Fire Dragon", sprite:"dragon_fire", unlock:null,
    attack:"flamebreath", evolveTo:"emberwake",          // ラン中に進化しうる（決定事項4）
    move:{ maxSpeed:160, minSpeed:60, accel:320, turnRate:2.0, leaderSpeed:220, leaderPull:1.6, pathEndMode:"loop" },
  },
  ufo: {
    ja:"UFO", en:"Saucer", sprite:"ufo", unlock:{ hidden:true, … },
    attack:"tractorbeam", evolveTo:null,                 // 最初から完成した1手
    move:{ maxSpeed:170, minSpeed:0, accel:INSTANT, turnRate:INSTANT, leaderSpeed:200, leaderPull:1.6, pathEndMode:"stop" },
  },
  …
};
```

- `flockWeapon` は「攻撃の種類（`kind`）」を指す内部値に戻し、竜種IDは `flockSpecies` として別に持つ。
- 影響範囲：`SPECIES_CHOICES` / `WEAPON_HUD` / `WEAPON_ELEMENT` / `mv()` /
  `CARD_DEFS` の `weapon:` フィルタ（→ `species:` へ拡張）/ ランセーブ（`flockWeapon` を保存中）。

**★`move` はプリセット名で持たない（決定事項5）**：
`move:"standard"` / `move:"instant"` のような**名前付きプリセットを API にしてはいけない**。
移動パラメータはバリエーションを作るために分離したものなので、
**竜種ごとに全項目を自由に組み合わせられる形**を維持する。
§3 のⅠ〜Ⅴのカテゴリは**読みやすさのための便宜的な分類**にすぎず、実装上の型ではない。
（共通値の重複を避けたいだけなら `Object.assign({}, MOVE_DEFAULT, 個別値)` で足りる。）

### 2-1. 「新種」と「上位進化」は最初から分けない（決定事項4）

24種すべてを**ひとつのプールとして扱う**。各竜種は
「開始時の攻撃」＋「（あれば）ラン中の進化先」を宣言するだけ。

- **最初から上位攻撃を撃つ竜種**があってよい（例：UFO の牽引光線、鯨竜の吸引爆縮、鮫竜の突貫）。
  その代わり進化先を持たない＝完成した1手で戦う。
- **基本攻撃から始めてラン中に進化する竜種**があってよい（例：火竜 炎息 → 焔跡）。
  こちらは伸びしろで戦う。
- つまり **A16〜A24 は「予備」ではなく、進化先として最初から使う**。
  上の表と §3 の割り当てで24種すべてが出番を持つ。

進化のトリガーは next-steps §3-2 型D（素材カードを max まで取ると上位が出現）に接続する。

## 4. アセット（1種 = 1枚。節約しない方針）

`assets/dragon_<id>.png` として**竜種ごとに専用スプライトを1枚**持つ。

| 状態 | 対象 |
|---|---|
| 既存流用 | 火竜（`dragon_fire_body` + `dragon_fire_wing`）／氷竜（`dragon_ice`）／影竜（`dragon_shadow`） |
| **新規（12枚）** | 緋竜（現状 fire の赤ティント → 専用画に）／隼竜／燕竜／蜂竜／**UFO**／鬼火／ガーゴイル／雷雲竜／鶴竜／鮫竜／亀竜／鯨竜 |

- **トップビュー厳守**。立面・ドームで描かない（過去に差し戻し実績あり）。
- UFO・鬼火は羽ばたきが無いので**コマ数を減らせる**（別の周期アニメ＝回転・明滅にする）。

### 4-1. プリレンダは「必要な種だけ・複数保持できる」形にする（決定事項2）

プリレンダは羽ばたき16コマで、火竜1種あたり約672KB。**15種を常時全部持つのはメモリが厳しい**ので
基本は選択中の種だけ生成する。ただし**「1種だけ」を前提にした作りにはしない**
（ラン途中で竜種が増える可能性があるため。将来的に群れに複数種が混ざる余地も残す）。

```js
// 種IDをキーにした要求時生成キャッシュ。上限を超えたら最も古いものから捨てる。
const spriteCache = new Map();          // speciesId -> フレーム配列
const SPRITE_CACHE_MAX = 3;             // 同時保持数（1固定にしない）
function getSpecieSprites(speciesId) {
  let s = spriteCache.get(speciesId);
  if (!s) {
    s = buildSprites(speciesId);
    spriteCache.set(speciesId, s);
    while (spriteCache.size > SPRITE_CACHE_MAX) {
      spriteCache.delete(spriteCache.keys().next().value);   // 挿入順＝最古から破棄
    }
  } else {                              // 参照されたら最新に回す（簡易LRU）
    spriteCache.delete(speciesId); spriteCache.set(speciesId, s);
  }
  return s;
}
```

- 現行 `dragonSprites[element]` の**属性キー固定をやめて種IDキーにする**のが実質の作業。
- 描画側（`drawBoids`）は「個体ごとに種を引く」形にしておけば、
  群れに複数種が混在しても同じコードで動く（今は `flockWeapon` 単一前提）。
- 上限3は暫定。1種あたり約672KB なので3種で約2MB。実機で調整する。
- 生成は `/gen-game-asset`（Gemini）と `C:\forge\ClaudeCodeForge`（Forge）で賄える見込み。
  トップビューの単体シルエットなので**人間製素材が大量に要る案ではない**。

## 5. UI とアンロック

- **4択メニューは15種に耐えない**（`showSpeciesSelect` はカードを縦積み）。
  グリッド＋スクロール、かつ**アンロック済みのみ表示**へ。
- 解放は `CHALLENGE_DEFS` / `evaluateChallenges` に接続（next-steps §3-7 の二層経済と噛む）。
  初期解放は**火竜のみ**、Ⅰ群の残り3種は早期に、Ⅱ〜Ⅴは腕前で解く。
- **UFO は隠し枠**（決定事項3）。条件を満たしたときだけ出る方が「変なものが混じった」驚きになる。
  ただし**設定外の異物ではない**：この世界の竜は「人間に奪われた卵を取り戻しに来ている」。
  UFO も**人間に奪われた何かを取り戻しに来た別の存在**と置けば、同じ動機の並行線として成立する
  （取り返しに来た者が人間を滅ぼす、という構造は竜とまったく同じ）。
  何を奪われたのかは narrative-designer に投げる余地あり（例：墜落した機体／同族の卵にあたるもの／
  地脈そのもの）。**竜と同じ動機で別の姿**という位置づけなら、隠し枠でも世界観は壊れない。
- **専用カード**：`CARD_DEFS` の `weapon:` を `species:` に拡張。15種×3〜4枚だと45〜60枚なので段階投入。

## 6. 進め方の推奨

1. **Ⅰ群の動きを統一**（`SPECIES_MOVEMENT` の**移動パラメータの上書きだけ**削除。
   `recoil`/`fireStun` は残す）。ほぼ削除だけで済み、「4種の操作感が同じ」を実機で確認できる。
2. **`SPECIES_DEFS` / `ATTACK_DEFS` の分離**（構造変更のみ・挙動は変えない）。
   同時に**スプライトを種IDキーの複数保持キャッシュ**へ（§4-1）。
   `drawBoids` を「個体ごとに種を引く」形にしておくと後で混成群れが作れる。
3. **Ⅱ群3種＋ガーゴイル**を追加（攻撃は全部「軽」段）。動きの違いが効くかを4種で判定。
4. 通れば **UFO・鬼火**（非生物枠）→ Ⅳ・Ⅴ群（重い攻撃）へ。
5. **進化（A16〜A24）は竜種が3〜4種そろってから**。素材カード→上位出現の機構を1本作れば横展開できる。
6. アセットは各段で必要ぶんだけ生成する。

## 7. 決定事項（2026-08-08・ユーザー判断）

第2案に対する回答。**以降の実装はこれに従う。**

| # | 論点 | 決定 |
|---|---|---|
| 1 | 緋竜の硬直 | **残す**。体当たりの硬直は操作性ではなく**攻撃手段に付随する**もの。→ `recoil`/`fireStun` を移動プロファイルから `ATTACK_DEFS` へ移設（§1-1） |
| 2 | プリレンダのメモリ | 基本は選択中の1種のみ生成でよいが、**1種前提の作りにしない**。途中で竜が追加される可能性があるため種IDキーの複数保持キャッシュにする（§4-1） |
| 3 | UFO の世界観 | **隠し枠でよい**。ただし「UFOが何かを取り戻しに来て人間を滅ぼす」設定は作れるので**完全に設定外ではない**（§5） |
| 4 | 予備の攻撃9種 | 上位進化は作りたいが、**「新種」と「上位進化」を最初から分ける必要はない**。最初から上位攻撃を撃つ竜種があってよいし、ラン中の進化が要る竜種があってよい（§2-1） |
| 5 | 動きの系統は5つで足りるか | **足りない**。案出しの便宜でカテゴリを作るのはよいが、**実装で5つに限定しない**。移動パラメータはバリエーションを作るために分離したものなので、自由に組み合わせて個性を出す（§1-3） |

## 8. 残る未決

   ただし「Ⅰ群4種は完全に同じ手触り」を厳密にしたいなら 0 にできる。**本書は保つ前提**。
2. **旋回半径の上限**：Ⅴ群（鯨竜157／亀竜127）は散らばりの目安180pxを超える見込み。
   `leaderPull` で締める前提だが**実機で群れが画面から溢れないかは要検証**。
3. **止まれる竜の震え**：`minSpeed 0` の UFO・鬼火は混み合うと小刻みに震える
   （v0.33.1 実測 約12回/秒/体）。機械のUFOなら味だが、**鬼火は要確認**。
4. **進化の割り当て**：§3 の「→進化」列は第1稿。組み合わせの妥当性は実機で入れ替えながら詰める。
