# Dragon Tide — 先行する特殊個体（検討メモ）

状態: **検討中**。案2・案3を先に実装し、それを触ってから案1の扱いを決める。
発端: Shooter「竜種のツリーのためにもう少し特殊個体を追加しようと思っています。
リーダーの近くを飛んで無敵状態でなんかする特殊個体を考えている」
→ 方向が定まったのは次の一文。

> 竜たちより先行しているっぽい特殊個体を作って、突撃系の進化の材料にしたい

つまりこれは**単体の特殊個体ではなく、突撃系ツリーの根**として設計する。

---

## 1. 動きの仕様（ここは決まっている）

### やってはいけないこと

操縦点（`leader`）に貼り付ける実装。Shooter 判定:

> リーダーそのものだと多分動きがUFOと同じ感じになりますよね？それだと不自然なのでダメです

そのとおりで、操縦点は `updateLeader` が指の位置へ直接動かす点なので、
貼り付けると**慣性ゼロで瞬間的に向きを変える**＝ UFO（`minSpeed === maxSpeed`・
旋回半径0）と同じ挙動になる。

なお**操縦点そのものは今どこにも描画されていない**（描いているのは指でなぞった線だけ）。
この特殊個体は操縦点の可視化が目的ではない。Shooter:
「操作点（リーダー）をみえるようにしたいわけでもないんですよね」。

### やること

**操縦点を追わせるが、群れと同じ慣性モデルのまま、性能だけ上げる。**

| | 通常の竜に対して |
|---|---|
| 最高速 | 1.2〜1.3倍 |
| 加速 | 速い |
| 旋回速度 | 上限あり（INSTANT にしない） |
| 追う先 | 隊列スロットではなく操縦点そのもの |
| 操縦点に着いたら | 止まらず**手前で回り込む**（`orbitRadius` 相当） |

こうすると指を振ったとき行き過ぎて弧を描いて戻る＝「速い斥候」に見える。
止まれば追いついて周回し、動けば前に出る。
**行き過ぎは不具合ではなく、生き物に見せるための要素**として残す。

## 2. 案の一覧

「前にいること」から何が取れるか、で4案出した。

| | 名前（仮） | 中身 | 評価 |
|---|---|---|---|
| 案1 | 先駆竜 | 群れとの距離をゲージにし、縮んだときに解放 | **保留**（§3の制約） |
| 案2 | 曳竜 | 航跡を残し、通った竜にバフ | **採用・先に実装** |
| 案3 | 楔竜 | 最初に触った相手にデバフ | **採用・次に実装** |
| 案4 | 鏃竜 | 前に出ている間、敵の攻撃を引き受ける（無敵なので無駄撃ちになる） | ストック |

Shooter 判定:
「案2はバフ、案3はデバフでわかりやすくアレンジもしやすいですね」
「案4のデコイは、もう一捻りあれば行けそうですが、一旦ストック案としておきます」

### 案2 曳竜（実装する形）

短時間だけ残る航跡を引く。**前にいるので群れは必ずその中を通る。**

効果は当初「通った竜が加速する」で考えていたが、**Shooter 指示で変更**:

> 案2は速度アップではなくて、次の直接攻撃の攻撃力アップにしましょう

→ **航跡を通った竜は、次の直接攻撃の威力が上がる。**

速度バフをやめた判断は妥当で、速度を上げると突進の発動条件
（群れ重心が最高速の 99.5%）に間接的に絡んで挙動が読みにくくなる。
威力バフなら効果が独立していて、数字も出せる（v0.99 のダメージ表示がそのまま効く）。

詰めるべき点:
- 「次の直接攻撃」の定義。ブレス（継続ダメージ）と弾と体当たりで
  竜種ごとに形が違うので、**1ヒット分に乗せるのか、一定時間乗せるのか**を決める
- 航跡の寿命・幅（長すぎると常時バフになって意味が薄れる）
- 乗っていることが見えるか（竜側に光を足すか、航跡側だけで足りるか）

### 案3 楔竜（実装する形）

接触した建物・敵に「ひび」を付け、以後しばらく**誰の攻撃でも余計に通る**。
常に一番先に触るので、群れは必ず柔らかくなった的を叩くことになる。

「先陣が壁を崩して本隊が雪崩れ込む」という突撃の絵そのもの。
弱点は**効いているのが分かりにくい**こと。ダメージ表示の数字が変わるだけだと
気づかれない可能性があるので、ひびの見た目を建物側に出すことが前提になる。

### 案4 鏃竜（ストック）

前に出ている間、敵が優先的にこいつを狙う。無敵なので初弾が無駄撃ちになる。

**常時だと v1.0.5 で上げた苛烈さを打ち消す**のが問題。
やるなら「新しい敵の射程に入ってから数秒だけ」のような時限にすべきだが、
条件が増えるぶん読みにくくなる。「もう一捻り」が要る、というのが現状の結論。

## 3. 案1 が抱えている制約（ここが今回の山）

### 溜めたものを何に使うか（出した案）

引き金と payoff は**噛み合っていないといけない**、というのが整理の軸。

距離が溜まる＝物理的には**ゴムが伸びている**。伸びたゴムの解放は爆発ではなく
**運動**なので、納得感を優先するなら payoff は動きになる。
その場合の引き金は「群れが追いついて距離が潰れた瞬間」。
逆にダメージを出したいなら「溜まっていたのは張力ではなく道中に仕掛けたもの」と
見立てを変える必要があり、そのときは「減速・停止」が引き金として合う。

| | payoff | 引き金 | 備考 |
|---|---|---|---|
| A 弾き出し | 群れ全体が先駆竜へ向けて強く加速。速度に乗った状態で着弾するので**そのまま突進が成立** | 距離が潰れる | 突進を受け身から能動に変えられる。突撃系の根としては最良 |
| B 牽引 | 溜まっている間、群れの最高速そのものが上がり続ける | 距離が潰れたら切れて溜め直し | 地味だが**操作が途切れない**。Aで「置いていかれる感じ」が出たときの差し替え先 |
| C 一斉起爆 | 道に落とした種が全部同時に爆ぜる | 減速・停止 | **溜めた量が画面に見えている**のが利点。敵の中を長く突っ切るほど強い |
| D 線が薙ぐ | 先駆竜と群れの間に張った線が閉じながら薙ぐ | 距離が潰れる | 距離＝武器の長さで納得感は最高。ただし6000棟の画面で長い線を閉じると当たり判定も見た目も散らかる |

推奨は **A を根に、進化で C を足す**形だった。
A だけだと溜め中が待ち時間になるが、C が乗ると道に光が並んでいくので
**待ち時間が準備時間に変わる**。

### 実際の制約 — 画面が狭い

Shooter 判定:

> 画面領域はあまり広くないので、先行する竜と群れとの距離は実はあまり取れない

数字で裏を取った。カメラ倍率は群れの数で決まる
（`CAM_SCALE_MIN_COUNT = 1.15` @ 10体 → `CAM_SCALE_MAX_COUNT = 0.6` @ 群れ上限）。
390×844 の画面でワールド座標に直すと:

| 群れ | カメラ倍率 | 見える範囲 | **短辺の半分** |
|---|---|---|---|
| 10体（開始直後） | 1.15 | 339 × 734 | **170** |
| 上限（55体） | 0.60 | 650 × 1407 | **325** |

先行竜も群れも画面に収めたいので、**取れる距離はせいぜい 170〜325**。
町の外縁半径が 170〜430 なので、**最大でも町1つぶんの幅**しか開かない。

しかも**開始直後がいちばん狭い**。ゲージの仕組みを覚えてほしい時間帯に
ダイナミックレンジが最小になる、という一番困る形をしている。

### 生き残る道（案1をやるなら）

ゲージの元を**その瞬間の距離**にするのをやめ、**積分量**にする。

- 「先行していた時間 × その間の速度」＝ **先行しながら走った距離**
- これなら画面の広さと無関係に溜まる。狭い画面でも、長く飛べば溜まる
- 「前に出ている」は溜まる**条件**に格下げし、溜まる**量**は走行距離が決める
- 案2（航跡）を作ると、この積分量は**航跡の長さ**として画面に出せる
  ——つまり案2の実装が、そのまま案1の可視化基盤になる

この形なら §3 の payoff 案（特に A と C）はそのまま使える。
C（一斉起爆）は「道に落とした種の数」がまさに積分量なので、相性が一番良い。

## 3.5. 専用スプライト（生成済み・v1.0.9）

挙動より先に絵を作った。`tools/gen_dragon_sprite.sh` の既定の型そのまま
（カテゴリA＝body + wing×1）。**アセットのキーは機構を表す英語**にした
（`wake` / `wedge`）。日本語の名前は仮なので、後で改名しても
ファイル名を作り直さずに済む。

| キー | 仮の名前 | 色 | 見た目 |
|---|---|---|---|
| `wake` | 曳竜 | 菫色 `#9b7bff` | 細身・矢型の頭・角は寝かせ気味。脇から細いリボンが後方へ流れる |
| `wedge` | 楔竜 | 緑青 `#5fbfa0` | 幅広・鈍い楔型の頭・重なった装甲板・背に鈍い棘の畝 |

色の選び方: 既存5体は金 `#ffd36b` / 石 `#b9a68c` / 淡青 `#9fd8ff` /
桃 `#f0a8ff` / 橙 `#ff7a4d` で、**空いている色相は緑〜青緑と青紫**だった。
そこを取っている。暗い緑の地面の上で沈まないことも条件。

### 2回作り直した記録

1. **楔竜の1回目は色が巌竜と被った。** 「weathered bronze with green patina」と
   書いたら緑青が乗らず**日焼けした真鍮**が出てきて、石の巌竜 `#b9a68c` と
   小さいサイズでは見分けがつかなかった。
   「STRICT COLOR RULE: 使うのは teal / sea green / dark cyan / near-black だけ。
   tan・sand・beige・gold・brown・bronze・暖色は一切禁止」と**禁止側を列挙**して解決。
2. **2回目は上下が逆になった**（頭が画像の下）。共通プロンプトの
   「snout pointing toward the TOP」だけでは足りなかった。
   「ORIENTATION IS CRITICAL: 頭が上辺、後脚が下辺。頭が絵の一番上」と
   **文頭に置いて**通った。§7 の落とし穴に足す価値がある。

### 実測メタデータ

生成物は長辺を 320px に揃えてある（既存5体と同じ）。

```js
wake: {
  bodyPivot:  { cx: 82.0, cy: 170.1, w: 165, h: 320 },
  shoulder:   { left: { x: 26.0, y: 140 }, right: { x: 139.0, y: 140 } },
  wingAnchor: { x: 317, y: 55.7 }, bodyDrawH: 27, wingDrawW: 25,
},
wedge: {
  bodyPivot:  { cx: 87.0, cy: 178.2, w: 175, h: 320 },
  shoulder:   { left: { x: 16.4, y: 141 }, right: { x: 157.6, y: 141 } },
  wingAnchor: { x: 316, y: 62.7 }, bodyDrawH: 27, wingDrawW: 25,
},
```

**曳竜の shoulder は自動推定を使っていない。** `sprite_meta.py` は
「胴体が一番横に張り出す行」を肩とみなすが、この竜は**脇のリボンが一番外に出る**ので
y=184（腰のあたり）を拾ってしまった。前脚の行 y=140 へ手で寄せてある。

`DRAGON_PART_SPRITES` には登録済みだが、`SPECIAL_DEFS` にはまだ入れていないので
**ゲーム中には出てこない**。16フレームの羽ばたきが正しく合成されること
（翼が肩から生えていて浮いていないこと）は画面で確認済み。

## 3.6. 案2 曳竜の実装（v1.1.0）

Shooter 指示で効果は「**次の直接攻撃1ヒットだけ**威力アップ」に確定。
「直接攻撃＝突進や一部の竜の近接攻撃および体当たり」という認識も提示された。

### 体当たりは全竜種が持っている（確認済み）

`updateCollisionAttacks` / `updateMoverRams` のどちらにも竜種の門番は無く、
**全個体が建物と移動敵に体当たりする**。違うのは威力だけ:

| | 1発の威力 | 再発動 |
|---|---|---|
| ふつうの竜 | 8 | 0.5秒 |
| 緋竜（武器 melee） | 25 | 0.35秒 |
| 巌竜（特殊個体） | 60 | 0.40秒 |

**重要なのは、緋竜の爪撃も突進の一撃も「体当たり」と別系統ではない**こと。
どれも同じ衝突ヒットで、倍率が違うだけ。だから「次の直接攻撃1ヒット」は
**1か所のフック**で表現できる（`consumeWakeCharge(i)` を2つの衝突処理に掛ける）。

実測: 町の中で群れ55体を10秒動かすと、体当たりは**竜1体あたり毎秒 0.5〜0.8回**起きる。
意外にも**火竜(0.81)のほうが緋竜(0.50)より多い**——緋竜は爪撃の硬直(`fireStun` 0.14)が
通常のヒットストップ(0.048)より長く、再突入が遅れるため。
つまりこの強化は**近接ビルド専用ではなく全竜種に乗る**。

### 実装

| | 値 |
|---|---|
| 一撃の倍率 | ×2.6（強化4枚で最大 ×4.6） |
| 航跡の太さ | 判定 26px（描画はその 0.38〜0.86 倍で一回り細く） |
| 節の寿命 | 2.2秒（強化3枚で +105%） |
| 節を落とす間隔 | 0.05秒 |
| 曳竜の最高速 / 加速 | ×1.25 / ×1.60 |

**前に出させるのに3つ必要だった。** 最初は最高速を上げただけで、
群れの重心より**平均17px**しか前に出なかった。原因は2つ:

1. **整列（alignment, 重み1.0）が周りの速度に合わせてしまう。** 曳竜だけ
   整列と結合を切った（分離は残す＝仲間と重ならない）。
2. **操縦点に近づくと減速する**（`BOID_ARRIVE_DIST` 70px の到着減速）。
   曳竜だけこれを外し、常に最高速で飛ばす＝**行き過ぎて弧を描いて戻る**。
   これが「速い斥候」の見た目を作る。

結果: 常時 200px/s（群れは160）で飛び、**73%の時間で群れより前**、
前後の振れ幅は −60〜+76px。操縦点に貼り付かないので UFO 化していない。

### 突進との切り分け

曳竜は最高速を超えて飛ぶので、そのままだと**突進の発動条件**
（群れ重心の速度が最高速の99.5%）を揺らす。1匹でも 48体の平均に
0.5%ほど効いてしまい、これは閾値の幅と同じ大きさ。
そこで `updateFlockMetrics` から曳竜を除外した。隊列に加わらない個体なので、
群れの計測から外すのは意味としても筋が通る。

一方、**一撃の倍率は突進の倍率と掛け算で重なる**。これは意図的で、
突撃系ツリーの伸びしろをここに置いている。

### 効き方の実測

| | 1発の威力 |
|---|---|
| 火竜 ふつう → 印つき | 8 → **20.8** |
| 緋竜 ふつう → 印つき | 25 → **65** |

印は当てた瞬間に消え、次の一撃は元の威力に戻る（＝1ヒットぶんだけ）。

**町での実戦で、印が乗った体当たりは全体の 27%**（10秒・群れ51体・衝突163回中44回）。
群れが体当たりする速さのほうが、曳竜が塗り直す速さより速いので、
**常時バフにはならない**。「航跡を通してから突っ込む」という位置取りが効く余地が残った。
群れ全体では体当たりの威力が実質 +43%。

FPS は 62 台を維持。

## 3.7. 案3 楔竜の実装（v1.1.1）

Shooter 判定:「とても良い感じですね。**無敵じゃないですがその方がよいです。**
現状の方針で行きましょう」。
→ 当初の「無敵の特殊個体」という前提は**取り下げ**。先行する2体はどちらも
ふつうにダウンする（HP倍率で硬いだけ）。

### 中身

体当たりした相手に**ひび**を入れ、その間は**誰の攻撃でも余計に通る**。

| | 値 |
|---|---|
| ひびの間の被ダメージ | ×1.45（強化4枚で最大 ×2.05） |
| ひびが残る時間 | 4.0秒（強化3枚で +90%） |
| 楔竜の体当たり | 22・0.45秒ごと（通常8／緋竜25／巌竜60） |
| 最高速 / 加速 | ×1.14 / ×1.35（曳竜の ×1.25 / ×1.60 より鈍い＝装甲のぶん） |
| HP | ×2.2 |

### 「誰の攻撃でも」を通すのに4か所要った

建物へのダメージは**1つの関数に集まっていない**。性能とFXの都合で
経路ごとに `hp -=` を直に書いているため、ひびの倍率はそれぞれに掛ける必要がある:

| 経路 | 場所 |
|---|---|
| 弾・爪・灯竜の光条・機竜の爆発など | `damageBuilding()` |
| ブレス（毎フレームの継続ダメージ） | `updateBreathAttacks` 内の直接減算 |
| 体当たり | `updateCollisionAttacks` 内の直接減算 |
| 虹竜のブレス | `updateMotherBreath` 内の直接減算 |
| 移動敵への全ダメージ | `damageMover()`（ここは1か所に集まっている） |

洪水（`DAM_FLOOD_DAMAGE`）だけは掛けていない。環境側の効果で、
「ひびが入った建物は洪水にも弱い」は理屈が通らないため。

実測: 建物 10 → **14.5**、移動敵 50 → **72.5**。どちらも ×1.45。

### 見えないと意味がない

設計メモの段階で「効いているのが分かりにくいのが弱点」と書いていたので、
**相手の輪郭に3本のひび線を重ねる**。角度は相手の座標から決めるので毎フレーム同じ
（乱数を振るとチカチカして読めない）。残り時間で薄くなるので、いつ切れるかも見える。

最初 1.4px・alpha 0.30 で描いたら**赤い建物の上で拾えなかった**ので、
2.1px・alpha 0.55〜0.95 まで上げた。

描画のために「今ひびが入っているもの」だけを小さな配列（上限64）で覚えている。
建物は6000棟あるので**毎フレーム全部は走査しない**。期限は建物側に書き、
配列は描画時に間引く。

### 性能

同じ町に群れ40体を置いた状態での A/B:

| | FPS |
|---|---|
| 楔竜なし | 30.5 |
| 楔竜あり | 27.8 |

この場面自体が重い（密集した町に群れを止めて炎とパーティクルが溜まる条件）ので
絶対値は低いが、**楔竜の追加ぶんは 9% 程度**。通常のプレイ場面では 60fps 台を維持。

### 残った調整どころ

- 楔竜の体当たりの間隔は 0.45秒だが、実測では**毎秒1回**しかひびを入れられていない
  （飛び回っているぶん建物に当たり続けない）。効果時間4秒に対して薄いかもしれない
- 曳竜と楔竜を**同時に連れると**、ひび ×1.45 と航跡 ×2.6 が重なって
  体当たり1発が最大 ×3.8 になる。特殊個体の枠は既定2なので実際に起こりうる

## 3.8. ひびを「見える」ようにする（v1.1.2）

Shooter 判定:「**『ひび』が見た目に全然わからないので実感がない**」。

原因を調べたら、見た目だけの話ではなかった。

### 原因1: そもそも ひびが入っていなかった

実戦の画面を止めて数えたら、**7秒間で active な ひびが 0** だった。
楔竜は到着減速を外してあるので操縦点のまわりを高速で大きく旋回していて、
**建物の隙間をすり抜けて当たっていなかった**。

直した点:
- **ひびを点ではなく面で入れる**。ぶつかった場所を中心に半径92px の建物と
  移動敵をまとめて割る。光った範囲がそのまま「ここを殴れ」になる。
  攻城槌が壁ごと崩す、という絵とも合う
- 楔竜だけ**体当たりの当たり半径に +8px**（装甲の張り出し）

結果、同じ場面で**5秒間に7回**面ひびが入るようになった。

### 原因2: 印が地味すぎた

線3本・2.1px では、赤い建物と炎とダメージ数字の中に埋もれていた。3層にした:

1. **塗り** — 相手を1棟ぶん覆う（alpha 0.30）。竜が重なっても色が透ける濃さ
2. **脈打つ輪** — 本体より一回り外（半径 ×1.28〜1.38）。小さい建物でも輪郭が出る
3. **ひび線** — 黒い縁 + 白い芯の2パスにして「割れている」質感を出す

さらに**入った瞬間の弾け**（外へ広がる teal の輪）を足した。
印が出ているだけでは「今かかった」が分からないため。

### 原因3: 効果そのものが数字でしか分からない

ひびが入っている相手に出るダメージ数字を**楔竜の色で出す**ようにした。
「余計に通っている」ことは数字が大きくなることでしか分からないので、
どの数字がひびのぶんなのかを色で結びつける。

### ついでに見つかった不具合

**表示名が「楗竜」になっていた。** パッチを書くときに 楔 を `楗` と
書いたが、正しくは `楔` で、`楗` は「楗」という別の字。
`SPECIAL_DEFS` の名前・カード名・図鑑のタグの3か所が別の漢字で出ていた。

以降このメモに関わるパッチは**エスケープではなく生の日本語で書く**。
