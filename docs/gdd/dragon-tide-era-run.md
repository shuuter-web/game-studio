## 0. 一行で

**1ラン＝1つの文明に攻め込む。壊すほど相手は動員段階を上げて反撃してくるが、
文明そのもの（時代）はラン中ずっと変わらない。**

---

## 1. 二つの軸を分ける（v0.56 の核心）

v0.51〜v0.55 は「壊すほど人類が時代を進める」構成だった。石器の街が神殿になり
城塞になる、という絵は派手だったが、**1ランの十数分で文明が数百年進むのは
世界の理屈として無理があった**（Shooter指摘）。

そこで軸を2本に分離した。

| 軸 | 何を決めるか | いつ変わるか |
|---|---|---|
| **時代 `runEra`** | 建築・色・敵の顔ぶれ・兵器の種類・地形の色味 | **ラン中ずっと固定**。開始時に選ぶ |
| **動員段階 `powerTier`** | 強さ（HP・火力）と物量（守備隊の頭数） | 破壊率30%ごとに 1→4 |

**時代はフレーバー、段階は強さ。**この2つは互いに独立している。
石器時代の街は最後まで石器時代の街のまま、ただ必死になって固くなる。

`currentStage` は `runEra` と常に同値で、`STAGE_CONFIGS` の参照先として使う。

## 2. ラン構成

| 要素 | 仕様 |
|---|---|
| 1ラン | 1文明 = 1マップ。目安10〜15分 |
| ラン開始の選択 | **攻め込む文明 × 竜種**。初回ランだけ選択なし（石器×火竜で即開始） |
| 進行 | 動員段階が4段。破壊率30%で次の段階へ |

| ラン毎の変化 | 文明 × 大陸シード（地形・町配置・首都位置・川） × 竜種 |

## 3. 動員段階（ラン中の強化）

### 3.1 引き金は破壊率

`tierDestroyRatio() = 1 - 現存する破壊対象 / その段階の開始時の破壊対象`

- 閾値 **30%**（`TIER_ADVANCE_RATIO`）を超えた瞬間に段階が上がる
- 分母は段階が上がるたびにリセットされる
- 城壁と首都は分母・分子どちらにも数えない

### 3.2 段階が上がると起きること

1. **非モーダルの演出**。プレイは止めない。フラッシュ(0.35s)＋スローモー(1.2s)＋
   見出し(2.2s)だけ。見出しは `決戦 / STONE AGE — PHASE 4` のような表記
2. 生き残った建物が**補強される**（HP・火力が段階倍率ぶん上がる）。
   **建築は変わらない**——同じ文明の同じ建物が、色だけ一段締まる
3. 廃墟の**3割が再建**される（同じ文明が同じ場所に建て直す）
4. **守備隊が増える**（顔ぶれは時代のまま、頭数だけ ×1.0 → ×2.0）
5. 群れの上限が開く（§5）
6. 首都は**一切変わらない**（最初から最強・§4）

### 3.3 段階の倍率

```
POWER_TIER_BOOST = [ 平時 hp1.00/dmg1.00, 動員 1.35/1.20, 総力戦 1.80/1.45, 決戦 2.40/1.75 ]
TIER_MOVER_MULT  = [ 1.0, 1.3, 1.6, 2.0 ]
```

建物の実効倍率 = **時代の底上げ（`STAGE_DIFFICULTY_BOOST[runEra]`）× 段階倍率**。
時代が文明ごとの基礎難度を、段階がラン中の伸びを担う。

## 4. 最初から最強の陣営

「強化しながらボス直行でも倒せてしまう」を道中で止めるための壁（Shooter指示）。

| 対象 | 段階 | 挙動 |
|---|---|---|
| 首都（ボス） | 最大段階 × `CAPITAL_POWER_MULT`(2.6) | ラン中一切変化しない。削った傷は残る |
| 首都区画 | 最大段階で固定 | 補強も再建もされない |
| 要塞都市（ボスに近い2〜3町） | 最大段階で固定 | 同上。落としたら落としたまま |
| ランダムな25%の街 | +1段階 | 段階とともに上がり続ける |
| 残り | 0 | 段階どおり |

- **段階固定（`_fixedTier`）の建物は補強も再建もしない。** 削った傷が残り、
  落とせば落としたまま＝攻略が積み上がる
- 要塞は**最大段階のさらに1段濃く**塗る。そうしないと段階4で普通の街と同じ色になり、
  格上であることが見た目で分からなくなる
- **首都の大技（極太レーザー）は時代を問わず出る**。今後 時代・文明に合った技に
  差し替えていく（§9-1）。街側の兵器（焼夷塔・ロケット砲台）は
  `stageFeatures(currentStage)` のまま＝時代どおりなので、文明の手触りはそちらが担う

## 5. 群れ：削らない、代わりに上限を解放する

**段階が上がっても群れは削らない。** 1ランで 1体 → 上限まで、1回の長い成長弧を描く。
代わりに上限が段階で開く（`TIER_FLOCK_CAP_FRACTION = [0.55, 0.70, 0.85, 1.0]`）。
既定で 55 → 70 → 85 → 100。段階遷移が損ではなく**解放の瞬間**になる。

## 6. マップ

| 項目 | v0.48 まで | 現在 |
|---|---|---|
| ワールド | 4800 × 3600 | **9600 × 7200**（面積4倍） |
| 町の数 | 10〜13 | **50〜65** |
| 建物数 | 1600〜2100 | **5300〜9000** |
| 動く要塞 | 7〜40 | 21〜124（段階で最大2倍） |
| ミニマップ | 80 × 60 | 120 × 90 |

数量は `scaledForWorld(基準個数, 密度係数)` で面積比から決める（基準 4800×3600）。
町は `TOWN_DENSITY_FACTOR = 1.25`、動く要塞は `MOVER_DENSITY_FACTOR = 0.75`、
岩山・湖・森は面積比そのまま。

### 6.1 前提となる技術改修：レイヤーのタイル化（v0.49）

地面レイヤーと建物レイヤーはワールド全面のキャンバスだった（4800×3600 で約138MB）。
面積4倍にすると553MBになりモバイルで落ちるため、**1200角のタイルに分割して
可視範囲だけ保持する**方式に改めた。常駐メモリは可視範囲に比例（実測 最大88MB）。

- 各タイルの ctx に `translate(-tileX,-tileY)` を掛け、既存のワールド座標描画を流用
- 転送はスクリーン座標で整数に丸める（隣接タイルが同じ境界を共有＝継ぎ目が出ない）
- 同じ場所を焼き直すときは**キャンバスを捨てずに使い回す**（7.6ms vs 80.5ms）
- 地表のむらはステージ生成時に位置を確定させる（焼くたびに引くとタイルごとに模様が変わる）

## 7. セーブ / 再開・報酬

- 段階が上がるたびにオートセーブ。保存するのは `runEra` と `powerTier`
- 町の破壊状況までは保存しない。再開はその段階の頭（再建済み）から組み直す
- 段階遷移ごとに竜晶。ラン終了（首都撃破）で全クリアボーナス＋次の文明を解放

## 8d. v0.53 の変更（Shooter指示）

**ボスは時代で強くならない。ラン開始時点で最強。**

| | v0.52 | v0.53 |
|---|---|---|
| ボスHP（時代1） | 1787 | **5448** |
| 時代2 / 3 / 4 | 2591 / 3757 / 5448 | **5448 のまま** |

## 9. 積み残しの論点

### 9-0. v0.55（大陸選択）の実測

- 初回ラン: 大陸選択を出さず 黎明×火竜で即開始（`isFirstEverRun()` 判定）
- 2回目以降: 「大陸を選ぶ」→「竜を選ぶ」。竜種の「もどる」は大陸選択へ1段戻る
- 未解放の大陸はカードが暗くなり、押しても反応しない（解放条件を本文に出す）
- クリアで次の大陸が解放され、リザルトに `🔓 ◯◯の大陸 が解放された` が出る
- 5大陸すべてで開始時代・時代の並び・ボスの時代が想定どおりであることを確認
- `elementFromPoint` で全カードが到達可能・タイトル(z50)が選択中は隠れていることを確認
- つづきからが開始大陸を保つ（`startEra` を runSave に保存）

### 9-1. ボス武装のバリエーション（次の作業・Shooter方針）

現在ボスの大技は極太レーザー1種のみで、`STAGE_FEATURES.bossLaser` の真偽で
出る／出ないが決まるだけ。**時代・文明に合った武装を増やしていく。**

- 参照するのは常に `runBossEra()`（ボス自身の時代）であって世界の時代ではない
- 方向性の例: 石器＝巨岩の投擲／古代＝神殿からの光の柱／中世＝城壁全周からの一斉射／
  近世要塞＝多連装砲／産業＝蒸気の熱波／電気＝極太レーザー（既存）／
  大戦＝絨毯爆撃／最終＝軌道爆撃
- 実装の受け皿は `STAGE_FEATURES` を「ボス技リスト」に拡張する形が素直
  （`bossLaser: true` を `bossArts: ["laser"]` のような配列にする）



- 大陸ごとの「特異点」修飾（例: 火山帯 / 重装の国）でラン変化をさらに増やす案 — 第2弾として保留
- 時代遷移時の建て替えで、プレイヤーが目の前で見ている町が変形する際の当たり判定の連続性
- 復興した町の湧き位置（廃墟跡そのままか、少しずらすか）
