# おかしの家 — 魔女が帰る前に、たべつくせ

手描きの線が沸くボクセルのお菓子を、**タップだけで食べ尽くす**パズル。1タップ＝ひとくち＝1ターン。
お菓子にはギミックがあり、放っておくとクリームが増える・口の中で弾けて周りも食べる・同じ味が全部なくなる・
次のひとくちが大きくなる、などが混ざっている。口数の上限内に全部食べればクリア。

設定は Sprint 19 の「お菓子の魔女の家」（`ideas/seeds/PS-052-okashi-no-ie.md`）。
土台は SKETCH VOXEL PUZZLE（v0.1.0、汎用の「土・石・鉄・苔…」）で、v0.2.0 で読み替えた。

```
prototypes/voxel-puzzle/index.html をブラウザで開くだけ
?level=7      … ステージを指定して開く
?seed=12345   … クリームの出る場所・マシュマロのちぎれ方を固定（既定はステージIDから決まる固定シード）
```

操作: **タップでひとくち / ドラッグで回す / ピンチ・ホイールで寄る**。キャラメルはタップしても「×」が出るだけ。
**下からはかじれない**（上か横が空いているお菓子だけかじれる）。

## お菓子（15種）

| 記号 | 名前 | ルール |
| --- | --- | --- |
| `#` | クッキー | ふつうのお菓子 |
| `H` | 飴 | 2回かじらないと食べられない（1回目でひび） |
| `X` | キャラメル | 歯にくっつくので直接はかじれない。パチパチ・ポッキー・大口に巻き込む |
| `M` | しぼり袋 | 毎ターン、隣の空きにクリームを1つしぼり出す |
| `m` | クリーム | しぼり袋が出したもの。増えはしない |
| `E` | シュークリーム | 3ターン経つと破裂して、しぼり袋になる（残りは面の刻みの数） |
| `S` | マシュマロ | かじると2つにちぎれてクッキーが増える。連鎖で食べればちぎれない |
| `B` | パチパチキャンディ | 口の中で弾けて周り3×3×3をいっしょに食べる |
| `I` | ウエハース | 隣が食べられると崩れる。ウエハースづたいに伝わる |
| `r` `b` `y` | グミ（いちご・ソーダ・レモン） | 1つ食べると同じ味が全部なくなる |
| `+` | 大口アメ | 次のひとくちが3×3×3。2つ同時になめると5×5×5 |
| `=` `\|` `/` | ポッキー | 矢印の向き（x / y / z 軸）に一直線、全部食べる |
| `W` | ブラックコーヒー | 飲むと、クリーム・しぼり袋・シュークリームが全部消える |
| `P` | とうがらしチョコ | **v0.2.0で追加。** 辛い。食べると水を飲むあいだに1ターン余分に過ぎる（しぼり袋が2回しぼる、シュークリームが早く破裂する） |
| `C` | とけたチョコ | **v0.2.0で追加。** 毎ターン、下が空いていれば下へ（必ず）、ふさがっていれば横のどこかへ、チョコだれを1つ出す |
| `c` | チョコだれ | とけたチョコが出したもの。増えはしない |

ターンの流れ: ひとくちの範囲を食べる → 連鎖を「波」ごとに解決（パチパチ・グミ・ポッキー・コーヒー・ウエハース）→
しぼり袋がしぼる・チョコがたれる・シュークリームのカウントが減る（とうがらしの分だけ、これがもう一周する）→
口数が上限に達していれば失敗。

## ステージの並べ方（30ステージ）

**1ステージで新登場するお菓子は1種だけ**（グミ・ポッキーのように組で使うものは組で1種）。
新登場したら、そのお菓子が主役のステージを2つ続ける。説明パネルでは新登場を先頭に NEW で出す。

| 新登場 | ステージ |
| --- | --- |
| クッキー | L01 |
| パチパチキャンディ | L02 L03 |
| ウエハース | L04 L05 |
| 飴 | L06 L07 |
| グミ | L08 L09 |
| 大口アメ | L10 L11 |
| キャラメル | L12 L13 |
| ポッキー | L14 L15 |
| しぼり袋 | L16 L17 L18 |
| シュークリーム | L19 L20 |
| ブラックコーヒー | L21 L22 |
| マシュマロ | L23 L24 |
| とうがらしチョコ | L25 L26 |
| とけたチョコ | L27 L28 |
| 総合 | L29 L30 |

「増えるお菓子」の紹介ステージは、**下からはかじれない**ルールで作っている。しぼり袋・とけたチョコの
下だけを空けておくと、そこへクリーム・チョコだれは出るのに、本体はかじれない（上をどかすまで）。
増える様子を必ず一度は見せてから、止め方を考えさせる形になる。

## 構成

- `puzzle-core.js` … ルール本体。描画から独立していて Node からも `require()` できる
- `levels.js` … 30ステージ。段ごとの文字列で書く（下の段から、奥の行から）。`intro` が新登場の記号
- `solve.mjs` … ビームサーチでステージの最短口数を求める。`par` と `limit` の根拠はこれ
- `index.html` … 描画・演出・入力（描画は voxel-sketch のもの。線は毎秒10コマ引き直され、常に沸いている）

```
node prototypes/voxel-puzzle/solve.mjs            # 全ステージの最短口数。par と食い違えば exit 1
node prototypes/voxel-puzzle/solve.mjs L26 --width 2000
```

ステージを足したり直したりしたら、まず solve.mjs を通す。解けないステージ（キャラメルが残る等）はここで分かる。
最短口数にはとうがらしで失ったターンも入る。

## 描画で足したもの

- **面の上の記号**: 面の四隅を [0,1]² に対応させ、双一次補間で記号の折れ線を面の上に置く。
  記号も penLine で引くので、お菓子と同じように沸く。ポッキーの矢印は、貫く軸を含む面にだけ描く
- **連鎖の可視化**: ルール側が返す波を 130ms ごとに描画用の盤面へ反映する（真実は core、描画は遅れて追いつく）
- **膨らむ出現**: ちぎれ・クリーム・チョコだれ・破裂は中心からスケールして描く（沸きは boilFrame 基準なので線は乱れない）
- 床の枠とマス目、破片は床で一度はねる

## お菓子の形

**当たり判定とルールはどれも1マスのボクセルのまま**で、見た目だけを形ごとに変えている。
タップの当たりは立方体なので、丸いお菓子の隙間を押しても食べられる。

| 形 | お菓子 | 作り方 |
| --- | --- | --- |
| box | クッキー・ウエハース・キャラメル | 立方体のまま。家の壁や床になるものは、積んで見えるほうがいい |
| ball | 飴 | 球＋左上の光の弧。かじるとひびが入る |
| gummy | グミ3種 | 少しつぶれた粒 |
| oval | シュークリーム | でこぼこの皮。残りターンは下側の点の数 |
| cluster | パチパチキャンディ | 粒3つ。上の粒から描いて重ねる |
| pillar | マシュマロ | 立てた円柱（胴＋上面の楕円） |
| bag | しぼり袋 | 下をすぼめた円錐＋星口金 |
| swirl | クリーム | しぼった山を3段 |
| lolli | 大口アメ | 棒つきの渦巻き |
| stick | ポッキー | 軸に沿ったカプセル。1マスより少し長く、根元だけ素の生地 |
| cup | ブラックコーヒー | カップ＋取っ手＋湯気＋黒い水面 |
| chili | とうがらしチョコ | 先が細くなる曲がった実＋ヘタ |
| melt | とけたチョコ | 低く広がって手前に垂れる |
| puddle | チョコだれ | 平たい水たまり |

作りの要点。

- どれも「1マスの中心の画面座標」と「1マスぶんの画面上の長さ」から組み立てる。
  上下方向は `cos(pitch)`、水平な円の潰れ具合は `|sin(pitch)|` を掛けるので、回しても破綻しない
- 線は `penLine` で引くので、**箱と同じように沸く**
- 輪郭のゆらぎは分割数で割る（曲線は箱の稜線より細かいので、同じ振れ幅だと毛羽立つ）
- **上が空いているマスでは形を持ち上げる**（`SHAPE_LIFT`）。箱以外の形は1マスに収まるため、
  平らに敷き詰めた面の中では手前のマスの立方体に隠れて**1画素も描かれない**ことがあった
  （とうがらしで実際に起きた）。頭が面より上に出るところまで上げている
- 破片と凡例の見出しも、丸いお菓子は丸で描く

## 画面の収まり

お菓子が増えるほど説明パネルが縦に伸び、盤面を隠してしまう問題があった（実機報告）。直し方は2つ。

- **パネルに上限**：全体 `min(38vh, 380px)`、お菓子の一覧 `min(24vh, 220px)` で、溢れた一覧だけが縦スクロールする。
  見出しと操作の説明は常に見えたまま。溢れているときは一覧の下端をぼかして続きがあることを示す。
  `body` に `touch-action: none` が掛かっているので、一覧には `touch-action: pan-y` と
  `overscroll-behavior: contain` を明示してある（これが無いと指で動かせない）
- **盤面は測ってから置く**：HUD の下端とパネルの上端に挟まれた「空き」を測り、そこに収まる倍率 `boardFit` を
  掛けて空きの中央に描く。画面上の固定割合（以前は 0.46）で描いていたのが、隠れた原因。
  倍率は **yaw を一周ぶんサンプルして最大の広がりに合わせる**ので、回している最中に大きさが変わらない
  （実測：横長で `boardFit` の変化は最大 0.036）。ピンチの `zoom` とは別に掛けているので、寄る操作は効いたまま

## 検証

`node tools/check.mjs` に加えて headless Chromium で機械判定している。

- 例外・HTTPエラーが0
- 沸きの実測（10.0Hz）
- 実座標のタップで L02 がクリアになる／ドラッグで食べない／キャラメルはタップ拒否
- **全30ステージを solve.mjs の手順で通し、ルールと描画の写しの残り数が一致する**（60fps）
- マシュマロを直接かじると増える／とうがらしを先に食べるとターンが2進みクリームが2つ出る／飴をかじっている間にチョコが下にたれる
- パネルが 390px 幅からはみ出さない
- **全ステージで、お菓子が説明パネルに隠れていない**（盤面レイヤーの不透明画素の下端 < パネルの上端）
- パネルの高さが画面の 40% を超えない。背の低い画面（390×620）と横長（844×420）でも同じ
- 溢れた一覧が実際にスクロールする／`touch-action: pan-y` が効いている／パネルの上のドラッグで食べてしまわない
- 回してもお菓子がパネルに潜らず、盤面の大きさが変わらない
- **全30ステージで、盤面に置いてあるお菓子がすべて画面に出ている**（種類ごとの色の画素を数える。
  上のマスが埋まっていて意図的に隠れているものを除く）
