# 竜潮 / Dragon Tide — SKETCH

Dragon Tide のキャラクター（竜・敵）と建物を**手描き風ストローク**に描き換えた別バージョン。
本編 v0.70.0 から分岐（このバージョンは `GAME_VERSION = v0.1.0` で別採番）。

```
prototypes/dragon-tide-sketch/index.html   … http(s) 経由で開く（後述）
?sketch=off   … 描き換えを止めて本編と同じ絵で走る（A/B比較用）
?seed=12345   … 本編と同じくランを固定
```

## やっていること

スプライトPNGを**手で描き直したのではなく、コードで描き起こしている**。

1. 元PNGを縮小してアルファのマスクを取り、Moore近傍でシルエットの輪郭を追跡
2. Sobel で内部のエッジを拾い、勾配のヒストグラムから上位20%が残る閾値を毎回決める
3. 輪郭を Ramer–Douglas–Peucker で「引ける本数」の折れ線に落とす
4. 頂点をハッシュでずらし、中点を通す二次ベジェで結んでインク線として描く
5. 元絵を1〜3pxずらして下塗りにし（版ズレ）、白を `source-atop` で乗せて明度を上げる
6. 暗い領域には斜線ハッチ

明度の閾値だけで内部を描くと、建物のように階調が近い絵では屋根も窓も1本も出てこない。
線にすべきなのは「暗い所」ではなく「変わり目」なので、内部は Sobel のエッジを使っている。

## 本編との差分の入り方

**描画コードは1行も変えていない。** 画像辞書（`enemyImages` / `buildingImages` /
`dragonImages` / `dragonPartImages`）を Proxy にして、読み出したときに手描き版の canvas を
返すようにしただけ。ピボット・回転・ティント・サイズ計算・アニメーションは本編のまま動く。

- 出力canvasは**必ず元画像と同じ寸法**で作り、`naturalWidth` / `naturalHeight` を持たせる。
  本編のピボット計算（とくに翼の付け根 `wingAnchor`）が natural サイズを読むため、
  寸法を変えると翼がずれる
- 生成は遅延。実際に画面へ出たスプライトしか焼かない。読み込み完了後に
  `prebakeSketches()` が空き時間（1回8ms以内）で残りを埋める
- 生成に `random()` / `fxRandom()` を使わない（乱数列を消費するとシード再現が壊れるため）。
  線のゆらぎは座標のハッシュから作っている

## アセット

`../dragon-tide/assets/` を参照している（7MBのPNGを複製しない）。本編の絵が差し替われば
手描き版も自動で追従する。`tools/check.mjs` はこの相対参照も実在チェックの対象にしている。

## 既知の制限

- **`file://` で直接開くと本編と同じ絵になる**。canvasが汚染されて画素を読めないため
  （コンソールに1度だけ警告が出る）。GitHub Pages かローカルサーバ経由で開くこと
- 手描き化の対象はキャラと建物のみ。地形（岩・湖・畑・森）と地面タイルは本編のまま
- 図鑑のサムネイルは `<img>` で元PNGを直接出しているので本編の絵のまま
- 焼いた canvas をスプライトぶん保持するので、その分メモリを使う（104枚）
- 線は静止。手描きアニメの「線が沸く」表現は、ボスの輪や竜のフレームキャッシュと
  相性が悪いので入れていない

## 検証

`node tools/check.mjs` に加えて、headless Chromium で以下を機械判定している。

- 手描きON/OFFの両方で例外・HTTPエラーが0
- 104枚すべてが解析に成功して焼けている（`skipped` が0）
- 同じシードでON/OFFの世界生成が一致（＝スケッチ生成が乱数列をずらしていない）
- 実プレイ画面に色が出ている（描画事故のあぶり出し）
